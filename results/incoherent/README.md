# Logically incoherent responses from ConflictBank

Generated by `scripts/gen_incoherent_responses.py` from `data/conflictbank-n100.jsonl`.

Each ConflictBank record carries one claim that is **true** of the world plus two
contexts: `c_{aid}_0` supports it, `c_{aid}_1` fabricates a story that cannot hold
together with it. (The atom id is index-dependent — record 0 has `a0`, record 7 has
`a7` — so nothing here hardcodes `a0`.)

## The incoherence pattern

`assert-both-then-negate`. Every generated passage:

1. asserts the true claim as fact,
2. adds supporting detail from the supporting context,
3. asserts the fabricated account as fact too,
4. states explicitly why the two cannot both hold,
5. concludes by asserting the **negation** of the true claim.

So one narrator asserts X and ¬X. The prompt bans hedging and attribution
("reportedly", "some sources say") because hedged prose is a *correct report about a
disputed claim* — the relation miner rightly reads it as coherent, which would defeat
the dataset. Every generated record carries a `hedges` field; it was empty on all
instances measured.

### Validating the pattern by regex — a caution

Spot-checking the corpus with a keyword regex under-counts. Searching for the literal
phrase "mutually exclusive" flagged 4 of 44 passages as missing the bridging step; all
four turned out to be correct, using "cannot be X while simultaneously Y", "cannot be
owned simultaneously", and "cannot coexist" instead. The models paraphrase the bridge
freely. If you need a pass/fail gate on the pattern, score the passage (a coherent
passage will not produce conflict edges) rather than grepping for a phrase.

`counts.n_ok + counts.n_failed == counts.n_total` always holds: a per-item failure is
recorded as `error`/`traceback` fields on the record, never raised, so one bad instance
cannot abort a sweep.

## Reading the LCS scores

Two cautions, both measured rather than assumed.

**The mining config matters, a lot.** The library defaults (`all_pairs` + `logprobs`)
saturate every mined weight to exactly 0.00/1.00 on this material. A contradiction at
`p=1.0` puts a hard zero in the both-true cell, and ~20 of those over 6 atoms leave the
all-false world as the only satisfying assignment, so `mean_marginal` collapses to
exactly `0.0` — a degenerate number that says nothing about the response. The script
therefore pins `windowed` (window 4) + `verbalized`, which mines graded weights. Each
scored record carries `mining.saturated`, `p_min`, `p_max`, `n_distinct_p` so a
degenerate graph is visible rather than mistaken for a low score.

**Scores are not comparable across miner models.** The same passage scored with Claude
as the miner gave `p ∈ [0.075, 0.49]` and `mean_marginal = 0.490`; with RITS gpt-oss,
`p ∈ [0.25, 0.97]` and `0.771`. Both rank it incoherent; the absolute values differ.
Check `config.model_id` before comparing two files.

**`log_partition` is within-response only.** It normalizes each response against its own
edge skeleton (`log_z_max`), so it must not be used to rank instances. Record it, don't
sort on it.

## Reproducing

```sh
# Smoke-test the prompt on one instance, with all four readouts (the acceptance gate).
python scripts/gen_incoherent_responses.py --frontier claude --smoke \
    --merlin-path /path/to/merlin

# The bulk dataset (generation only; ~23 s/instance measured).
python scripts/gen_incoherent_responses.py --rits-model gpt-oss-120b-a100

# With scoring (1-3 min/instance on top).
python scripts/gen_incoherent_responses.py --rits-model gpt-oss-120b-a100 \
    --limit 5 --score --merlin-path /path/to/merlin
```

Frontier models (`--frontier claude|gpt`) are hard-capped at 10 instances; the flag is
for validating a prompt, not for bulk generation. They run on the IBM LiteLLM gateway
through the `openai` backend kind, and the script bridges
`OPENAI_API_KEY ← ANTHROPIC_AUTH_TOKEN` since that is what `.env` carries.

Offline tests: `tests/test_gen_incoherent.py` (24 tests, no LLM, no Merlin).
