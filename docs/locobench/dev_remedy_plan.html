locobench-claude-5-test · 14 families · 70 items · remedy plan

Repairing the perturbed rungs of the LoCoBench dev set

The relation miners are no longer the bottleneck. Their ladder pass rates stay flat because the perturbed rungs do not say what their gold labels claim. A blind side-by-side reading found the planted change realized in only 5 of 39 dev transitions, and in 132 of 268 on the 100-family release. This plan fixes the operators, adds a realization gate at every rung boundary, regenerates only the affected rungs, and checks the result with judges that took no part in generating or gating it.

Prepared 2026-11-06 · scope: dev set only; the same code ports to the release afterwards · estimated spend ≈ $30, about 3 hours of wall-clock

Summary

  • Keep every base rung. Base rungs already passed V1, V3 and V4. Keeping them holds the item ids, atoms and plans fixed, and confines the change to the 40 perturbed rungs of the 8 CONFLICT and 2 CHAIN families.
  • Redefine four operators so that each edit has to remove or create a specific span of text that a checker can locate, rather than "change a connective".
  • Make labels follow text that has been checked. A new gate (V5) checks every rung boundary. A rung is admitted only when a majority of the committee reads the planted change, and only that change.
  • Audit with judges held out from the process (gpt-6.1-sol, claude-opus-5-5): neither wrote the text nor sat on the gate. Then re-measure gold and mined ladder pass rates on the repaired set.
  • Expect the gold arm's 0.81 to move. Part of it was earned on labels the text did not support, so the repaired number is the one to publish.

D1

A drop removes a connective, but the conflict lives in the framing

Asked about two claims in isolation, a judge rated 17 of the 18 dropped dev pairs compatible. The tension comes from the text's framing: "by contrast", "two mutually exclusive readings, exactly one of which must be right". P5's definition of the drop ("remove the connective … so the two atoms are merely adjacent") leaves that framing in place. A smaller group is incompatible on content alone: 1 of 18 dev pairs and 13 of 82 unrealized release pairs. No edit that keeps both atoms can drop those.

Fix: redefine the drop to delete every framing span, and exclude content-incompatible pairs from drop targets.

D2

No gate checks that a perturbed rung realizes its label change

V1 runs only on the base rung. After P5, the pipeline checks only that the text changed, that its length stayed within bounds, that adjacent label sets differ, and that identical texts carry identical labels. None of these reads the edit.

Fix: a new V5 realization gate at every rung boundary, with retry and then rejection.

D3

The spurious-relation text and its label disagree

P5 allows "a causal or contradictory link". The text almost always writes a causal one, while apply_calls hardcodes Contrast. So the "worse" rung's MRF penalizes a contradiction the text does not contain.

Fix: pin the operator to a contrastive link, and verify it.

D4

Resolutions can target conflicts that are already resolved

Target choice reads the plan's labels, not the text. Where the base prose already resolves the tension, adding a resolution changes nothing a reader can see.

Fix: pre-screen resolution targets against the base text, and require the resolution sentence to address both claims.

D5

Chain breaks can target links that are not chain links

A CHAIN ladder's "break" is meant to cut an inferential step. Breaking a Restatement changes an equivalence instead.

Fix: restrict break_chain targets to entailment edges.

Operator redefinitions

Every operator gets the same contract. The P5 diff must name the spans it removed or added, and a deterministic check must confirm that removed spans are gone and added spans are present before any LLM gate runs. That cheap check catches most failures without spending a judge call.

drop_relation(edge)D1
Find EVERY span that presents the two claims as related: connectives, framing sentences that set them against each other or call them alternatives, and any later sentence that refers back to their opposition. Delete or rewrite each span so the text still asserts both claims verbatim but no longer relates them. List each removed span verbatim in spans_removed.

Target filter: skip any pair that a content-only check rates incompatible (≈ $0.002 per pair). Deterministic check: no removed span may survive verbatim in the output.

spurious_relation(atom_a, atom_b)D3
Add ONE connective that sets claim A against claim B, so the text asserts they cannot both hold. Do not assert a causal, evidential or supporting link. Add no new factual content. Report the added span in spans_added.

The label stays Contrast. Now the text has to match it.

add_resolution(edge)D4
Add ONE sentence, after both claims, in which an authority reaches a determination that names BOTH claims and explains how the tension between them is settled. Leave the rest of the text unchanged.

Target filter: a reader must rate the edge an unresolved conflict in the base text (one V5-style call per candidate).

break_chain(edge)D5
Remove or negate the inferential step realizing this link, so the text no longer says one claim supports or leads to the other. Keep both claims verbatim. List the removed span.

Target filter: entailment-coupled edges only, in chain order.

V5: the rung realization gate

What it checks

  • Targeted edges: the side-by-side reading prompt from the reading check, applied to the lower and upper rung. The committee majority must read the planted change.
  • Untouched edges: 3 coupling-bearing edges that the edit did not target, sampled per boundary. The majority must read each one the same way on both rungs. This catches edits that spill over onto other relations, which also adds noise to the score differences the ladder checks compare.
  • Span check first: the deterministic span check runs before any LLM call.

How it decides

  • Raters: the existing committee (gpt-5.6-terra, gemini-3.1-pro, claude-sonnet-5), majority rule, each in a random text order.
  • On failure: retry P5 up to 3 times, with the gate's reason fed back into the prompt.
  • On a third failure: re-target to the next eligible edge once. If that also fails, reject the family, as the pipeline already does for a missing rung.
  • The generator never rates its own edits (rule R3, unchanged).

Risks

  • Deleting framing can make prose read like a list. The "coherent" rung loses two conflicts and gains a resolution. The V3 naturalness gate and the 15% length-drift limit catch the worst cases; Phase 1 tests this before the spend scales.
  • The gate shares its raters with V1 admission. Those raters could share blind spots. The Phase 3 audit uses two different models for this reason, and its numbers are the ones to report.
  • Fewer drop targets. Excluding content-incompatible pairs leaves CONFLICT families with fewer eligible edges. Every dev CONFLICT family has 4 conflict edges and needs 3. A family left without enough targets is rejected rather than patched, and the run report says so.
  • The fix to the miner's resolved-flag rule is already in place (resolution on any conflict coupling, not only on Concession). Re-measurement uses the corrected code.
