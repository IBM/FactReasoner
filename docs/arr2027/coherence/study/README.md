# docs/arr2027/coherence/study

The human study of the coherence paper, laid out like `docs/arr2027/locobench/study/`. Design,
deviations and analysis plan: `docs/arr2027/coherence/HUMAN_STUDY.md`.

- `brief.md`, `setup.md`: the annotator brief and the Label Studio setup (copied into every
  bundle).
- `labelstudio/`: the three Label Studio configs (edit pairs, answer rating, relation check),
  also copied into every bundle.
- `bundles/annotator_<k>/`: what annotator k receives, and nothing else. Load it with
  `python locobench_study_projects.py --bundle annotator_<k> --token <token>` (see `setup.md`).
  It contains Block A (48 edit pairs), Block B1 (13–14 answer ratings), Block B2 (52–56
  relation checks) and their practice files.
- `key.sha256`: the SHA-256 of the answer key. The key itself is
  `artifacts/coherence_study/key.json`, git-ignored, so the screens and their answers are never
  side by side in the repository. It is regenerated by
  `.venv/bin/python scripts/coherence_study_build.py --seed 20261128`.
- `exports/annotator_<k>/{blockA,blockB1,blockB2}.json` (after annotation): the Label Studio
  JSON exports, as received. Do not edit them.

The analysis is `scripts/coherence_study_analyze.py analyze --macros
docs/arr2027/coherence/numbers_human.tex`.

Every bundle passes a leak check (`check_no_leak` in the build script). Task files carry only
task text, and their ids are sequential (`A-0001`, `R-0001`, `K-0001`). No item type, version
name, family, item id, score or miner field appears in them.
